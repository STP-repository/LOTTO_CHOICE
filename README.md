# Lotto Best Choice

새로 작성한 React + TypeScript + Vite + Tailwind CSS + Recharts 웹 프로그램입니다. Node.js 수집기가 동행복권 실제 당첨 기록을 저장하고, 브라우저가 통계·추천·백테스트를 계산합니다. 학습형 AI 모델을 사용하지 않으며 당첨 확률 향상을 주장하지 않습니다.

공개 사이트: https://eogus3535-sudo.github.io/lotto-best-choice/

배포 계정: `eogus3535-sudo`. 주간 자동 갱신이 활성화되었고 첫 GitHub Actions 실행에서 공식 데이터 수집, 9개 테스트, 빌드, 배포가 모두 성공했습니다. 실행 기록: https://github.com/eogus3535-sudo/lotto-best-choice/actions/runs/39034075560

자동 갱신은 `.github/workflows/deploy.yml`에서 토요일 22:17, 일요일 07:17 KST에 실행됩니다. 공식 데이터 수집 → 검증·테스트 → 빌드 → 공개 사이트 배포 순서이며 사용자 PC가 꺼져 있어도 동작합니다. 수집 실패 시 정상 파일을 보존하고, 최신 데이터 검증이 실패하면 기존 공개 배포를 유지합니다. GitHub 예약 작업은 지연되거나 비활성 저장소에서 중단될 수 있으므로 Actions 실행 기록으로 상태를 확인하세요.

## 실행

Node.js 22.12 이상(권장 24), npm이 필요합니다.

```sh
npm ci
npm run dev
```

터미널의 로컬 주소(기본 http://127.0.0.1:5173)를 엽니다. 최초 수집한 정상 데이터가 포함되어 인터넷 연결이 없어도 분석할 수 있습니다.

```sh
npm run data:update  # 공식 데이터 수집 (인터넷 필요)
npm run typecheck
npm test
npm run report      # reports/backtest.json 생성
npm run build       # dist/ 생성
npm run preview     # 프로덕션 빌드 확인
```

- https://papaya5rhw1984.github.io/lotto-data/all.json ([제공자 문서](https://github.com/papaya5rhw1984/lotto-data))

두 미러는 공개 커뮤니티 데이터로 공식 보증이 없으며 서로 독립적이라고 가정하지 않습니다. 미러 사용 시 화면에 공식 미검증 출처를 표시합니다. 기존 공식 데이터와 겹치는 번호가 다르면 저장하지 않습니다. 원본 데이터만 참고했으며 기존 프로젝트 코드는 복사하지 않았습니다.

실행일의 한국 날짜에서 달력 기준 15년을 뺀 범위를 사용합니다. 회차별 번호 6개·보너스 범위(1–45), 중복 번호, 회차 중복·누락, 회차와 토요일 추첨일의 일치, 미래 날짜, 전체 15년 범위의 앞부분과 최신 예상 회차를 검사합니다. 토요일 22:00 KST부터 새 회차 제공을 기대하며 그 전에도 API에 게시된 당일 결과는 수집합니다. 날짜 계산은 한국 시간을 명시합니다.

수집 파일은 검증 후 임시 파일을 rename하여 교체합니다. 실패 시 `status.json`과 `data/last-error.json`에 기록하고 마지막 정상 `lotto.json`을 보존합니다. 브라우저도 검증된 마지막 데이터를 localStorage에 저장합니다. CSV는 사용자 제공 데이터로 명시하고 공식 대조 완료로 표시하지 않습니다.

## 통계와 추천

빈도 계산에는 보너스를 제외합니다. 전체·최근 10/30/50/100회 빈도, 고빈도·저빈도·미출현, 홀짝, 합계(20 단위), 연속 쌍, 구간, 함께 출현한 상위 15쌍, 직전 중복, 연도별 빈도와 최근 1년/100회 출현율을 차트·표로 제공합니다. 최근 1년은 마지막 관측 추첨일 기준입니다. 구간 41–45는 5개 번호이므로 다른 10개 번호 구간과 단순 비교에 유의합니다.

7가지 모드, 1/5/10게임, 번호 복사, 게임 내/간 중복 방지, 정렬, 내부 점수를 구현했습니다. 전체 통계와 고빈도 모드는 같은 빈도 기준입니다. 고빈도/저빈도는 각각 빈도/역빈도를 가중치로 삼습니다. 가중 비복원 추출 후보 중 점수가 높은 조합을 고릅니다(일반 8후보, 균형·종합 60후보).

`src/core/recommend.ts`의 `WEIGHTS`: 전체 빈도 35%, 최근 빈도 25%, 미출현 10%, 균형 30%. 빈도·미출현은 각 최댓값으로 나누어 정규화합니다. 내부 호환용 균형 점수는 홀짝과 구간 다양성만 사용하며 합계는 제외합니다. 공개 추천 방식은 아래 6개 선택지 설명을 따릅니다. 내부 점수는 당첨 확률이 아닙니다. 모든 조합의 1등 확률은 1/8,145,060입니다.

## 백테스트

최근 최대 100회에 대해 검증 회차 **이전** 기록만으로 매번 모델을 다시 계산합니다. 최소 30회 훈련 기록이 필요합니다. 각 훈련 집합도 해당 대상일 기준 최근 15년으로 제한합니다. 설치 파일에 포함된 15년 데이터보다 더 오래된 기록은 사용하지 않으므로 초기 검증 시점에는 훈련 기간이 15년보다 짧습니다.

Mulberry32 난수와 회차별 독립 시드를 적용합니다. 게임별 번호 일치 개수(보너스 제외)를 전체 게임에 걸쳐 평균하며, 최고 성적만 선택하지 않습니다. 동일 게임 수의 균등 무작위 비교군을 별도로 생성합니다. 0–6개 일치 분포와 회차별 그래프, 훈련 경계 및 상세 JSON을 제공합니다. 시드 변경/모드 탐색을 통한 성능 선택 편향이나 작은 표본의 차이를 우위로 해석하면 안 됩니다.

## CSV

UTF-8, 최대 5MB, 헤더:

```csv
round,date,n1,n2,n3,n4,n5,n6,bonus
```

데이터 관리에서 다운로드한 CSV를 편집해 업로드할 수 있습니다. 회차는 연속되어야 하고 날짜는 YYYY-MM-DD입니다. 부분 기간 CSV도 허용하지만 최근 15년 밖 기록은 분석에서 제외합니다. 업로드는 현재 브라우저에만 적용되며 공개 서버 원본을 바꾸지 않습니다.

## 무료 공개 배포 (선택: GitHub Pages)

Vite 정적 사이트와 GitHub Actions의 무료 공개 저장소 예약 실행을 함께 쓰는 구조입니다. 서버/API 키가 필요하지 않습니다. Cloudflare Pages와 Vercel도 `npm run build`, 출력 `dist`로 정적 배포할 수 있지만 이 프로젝트의 예약 데이터 수집과 배포는 GitHub Pages 워크플로우에 통합했습니다.

1. GitHub에 빈 **공개 저장소**를 만듭니다. 이 폴더를 git 초기화하고 `main` 브랜치에 전체 소스를 push합니다(`node_modules`, `dist` 제외).
2. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다.
3. Settings → Actions → General에서 워크플로우 실행과 repository contents 쓰기 권한을 허용합니다. 조직 정책/브랜치 보호가 있으면 워크플로우의 데이터 커밋 권한을 설정합니다.
4. Actions의 **Collect, verify and deploy Lotto Lab**을 수동 실행하거나 `main`에 push합니다.
5. 성공한 실행의 `deploy` 작업 Environment URL 또는 Settings → Pages의 실제 발급 URL을 확인합니다. 이 URL을 가족·친구에게 공유합니다.

`base: './'`로 저장소 하위 경로를 지원하며 메뉴는 클라이언트 상태로 바뀌어 경로 rewrite가 필요하지 않습니다. GitHub Actions는 토요일 22:17, 일요일 07:17 KST에 수집을 시도합니다. 예약 실행은 지연될 수 있고 기본 브랜치에만 적용됩니다. 장기간 비활성 공개 저장소에서는 GitHub가 예약 작업을 비활성화할 수 있으므로 Actions 화면에서 재활성화하세요. [Pages 설정 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [예약 실행 제한](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

수집 실패도 상태를 커밋하고 이전 배포는 유지합니다. 테스트가 최신 데이터 누락을 검출하면 새 배포를 중단합니다. 이후 수집이 성공하면 자동 배포를 재개합니다. 수동 브라우저 새로고침은 공식/미러를 직접 조회하되 CORS로 차단되면 배포된 정상 파일을 다시 확인하고 사용자에게 알려줍니다. 영구 서버 갱신은 `npm run data:update` 후 push 또는 Actions 수동 실행을 사용하세요.

## 추천 선택 화면

점수·상위 퍼센트 대신 하나의 추천 방식 필터에서 기존 7가지 방식 또는 추가된 15년 통합 추천을 고릅니다. 각 게임에는 홀짝, 합계, 구간 분산과 연속번호를 표시하며, 체크한 게임만 복사하거나 전체를 복사할 수 있습니다. 이 특징은 당첨 확률의 등급이 아닙니다. 개별 추천 방식은 유지하며, 통합 추천은 추가된 패턴 조건도 적용합니다.

## 번호 공개 애니메이션

추천 생성 시 공이 굴러가는 연출 후 첫 게임의 6개 번호를 순차 공개하고 번호가 모두 공개되면 확인 버튼으로 전체 게임을 보여줍니다. 화면은 자동으로 닫히지 않습니다. 생성된 번호를 보여주는 연출이며 추천 계산을 바꾸지 않습니다. 건너뛰기 또는 Esc로 즉시 결과를 볼 수 있습니다. 운영체제의 움직임 줄이기 설정에서는 회전 동작을 줄이고 번호 공개 화면은 유지하며, 생성 중 중복 클릭을 막고 타이머를 정리합니다.

## 15년 통합 추천 (추가 기능)

현재 통합 추천은 전체 8,145,060개 조합을 전수 검색합니다(src/core/ranking.ts). 무작위 후보 생성·선택, 번호 겹침 감점, 출처 분산을 모두 제거했습니다. 최종 점수의 상위 1~5위 또는 1~10위를 보여주며 동점은 숫자가 작은 조합부터 정렬합니다. 같은 데이터와 가중치이면 시드와 관계없이 같은 결과가 나오고, 5게임은 10게임의 앞 5개와 같습니다. 별도 무작위 모드는 유지합니다.

평가는 src/core/evidence.ts의 8개 지표를 사용합니다. 합계 지표를 제거했습니다. 번호 기록 80%: 전체 빈도·최근 100회·번호 쌍 각각 160/7%(약 22.86%), 미출현 80/7%(약 11.43%). 조합 구성 20%: 홀짝·구간·연속번호·직전 중복 각각 5%. 각 값을 100으로 나누어 가중치 합을 1로 만듭니다. 각 지표는 0~1로 정규화하며 가중치 합은 1입니다. 프로그램의 선택 설정이며 학습된 확률이 아닙니다. 화면의 ‘숫자를 분석하는 방법과 가중치’에 각 계산식을 표시합니다.

패턴으로 후보를 제외하거나 게임 수를 고정 배분하지 않습니다. 합계·평균·합계 분포는 점수와 순위에 전혀 반영하지 않고, 합계 자체는 화면의 정보와 통계 차트에만 표시합니다. 결과마다 ‘이 조합의 분석 근거’를 펼쳐 실제 참고 기록을 볼 수 있습니다. 게임 간 같은 숫자가 반복되는 것을 허용합니다.

전체 검색은 별도 웹 워커에서 실행하고 진행률·오류를 표시합니다. 정상 데이터가 바뀌면 캐시를 새로 계산하며 이전 데이터 계산은 중단합니다. 백테스트 역시 같은 전수 검색 엔진을 사용하고 각 대상 회차 이전의 기록만 씁니다. 비교군에만 난수 시드가 적용됩니다.

검증 재실행: npx tsx scripts/validate-evidence.ts. 최신 결과는 reports/ranking-validation.json입니다. 이전 evidence-validation.json과 soft-pattern-audit.json은 과거 가중 추첨 방식의 기록이므로 현재 엔진의 성능으로 해석하면 안 됩니다. 과거 기록을 재검증해도 완전히 새로운 미래 실험은 아니며 당첨 확률 우위를 입증하는 결과로 보지 않습니다.

추천 선택지는 통합 / 무작위 / 전체 빈도 / 최근 100회 / 미출현 / 번호 쌍의 6개입니다. 개별 조건은 해당 지표 하나만 가중치 1(100%)로 하고 다른 7개 지표는 0으로 평가합니다. 모든 통계 방식은 전체 조합을 점수순으로 정렬합니다. 개별 조건은 1/5/10게임, 통합은 5/10게임을 지원합니다. 동점 조합은 숫자가 작은 순서이며 다른 지표로 몰래 동점을 깨지 않습니다. 같은 번호 반복과 낮거나 높은 합계도 허용합니다.

홀짝·구간·연속번호·직전 중복은 단독 추천과 백테스트 메뉴에서 제거했습니다. 통합에서는 네 항목을 각각 5%의 보조 지표로 유지합니다. 개별 메뉴는 추가하지 않습니다.

80/20 비중은 사전에 정한 분석 설정이며 최적값으로 학습하거나 검증한 확률이 아닙니다. 변경 전후의 동일 회차·동일 게임 수 비교는 reports/weight-comparison.json에 기록합니다.

끝자리 계산·점수·추천 메뉴·통계 차트·추천 근거는 모두 제거했습니다. 번호 기록 그룹 내부 비율 2:2:1:2를 유지해 총 80%로 다시 환산하고, 구성 네 지표는 각각 5%로 유지합니다. weight-comparison.json은 끝자리 포함 시점의 과거 보고서이며 현재 성능을 나타내지 않습니다. 현재 검증은 validate-evidence.ts로 재실행합니다.

## QR 당첨 확인

메뉴의 `QR 당첨 확인`에서 카메라 스캔, QR 사진 업로드(20MB 이하), QR 주소 붙여넣기를 지원합니다. 로또 6/45 QR의 구매 회차와 최대 5게임을 읽고 해당 회차의 저장된 당첨번호 및 보너스와 자동 비교해 1~5등 또는 낙첨을 표시합니다. 추첨 전과 결과 데이터 미보유 상태는 확인 대기로 표시하며, 데이터 새로고침 시 다시 비교합니다. 미검증 CSV/미러 데이터는 출처를 표시합니다. 지급 여부는 원본 복권과 공식 결과로 최종 확인하세요.

사진·QR 원문은 저장하지 않습니다. 회차·구매 번호·당첨 결과의 최근 100건 확인 이력은 이 브라우저에 보관하며 서버로 전송하지 않습니다. 카메라는 HTTPS 또는 localhost와 브라우저 권한이 필요합니다. 지원 QR 형식은 4자리 회차 + 선택 방식(q/m/n/s)과 12자리 번호의 반복(1~5게임) + 선택적인 10자리 일련번호입니다. 형식이 다른 QR은 오류로 안내합니다.




## 메인 화면과 랜덤게임

링크를 열면 로또 공 애니메이션이 있는 소개 화면이 먼저 나타납니다. 프로그램 시작을 누르면 바로 입장하며 회원 등록은 요구하지 않습니다. 랜덤게임에서만 이번 게임 참가자 2~20명을 입력·선택합니다. 동일한 이름을 여러 참가자가 사용해도 내부 순번으로 구분합니다. 게임을 바꾸거나 다시 시작해도 명단과 체크 상태를 유지하고, 새로 등록을 눌렀을 때만 현재 명단을 비우며, 게임에 사용했던 이름은 브라우저의 최근 이름 목록에 보관하여 체크해 다시 사용할 수 있습니다. 이름은 서버로 보내지 않으며 계정·기기 간 동기화는 제공하지 않습니다.

게임 10종: 핀볼(마지막 도착자), 사다리 타기, 이름 룰렛, 구슬 경주(첫 도착자), 카드 뽑기, 주사위 대결, 이름 슬롯, 보물찾기, 폭탄 돌리기, 랜덤 토너먼트. 핀볼은 고정 시간 간격으로 중력·장애물 충돌을 계산해 실제 경로와 도착 순서를 재생합니다. 같은 참가자 순서·시드로 같은 결과를 다시 볼 수 있습니다.

## 통합 분석 · 15년 가중치 검증

기존 추천 필터의 15년 통합 추천, 최근 100회 흐름, 함께 나온 번호 쌍을 제거하고 새 통합 분석 진입점을 추가했습니다. QR과 기존 통계·백테스트 계산은 유지합니다. 전체 공식 이력은 public/data/full-history.json에 따로 수집하고 최근 15년 파일과 독립적으로 검증·갱신합니다.

새 분석은 빈도·마르코프·베이즈·편차·홀짝/고저·합계·구간·연속/끝수·AC/간격·다양성의 10개 항목과 기본 가중치 15/10/10/10/10/10/10/5/10/10%를 사용합니다. 랜덤워크, 30/50/100/200회 통계, 출현 간격, 이월수/이웃수를 계산합니다. Safety Σ는 실제 분포의 분위수로 꼬리 후보를 표시하고 Games Out Value는 균등 후보와 꼬리 비율을 비교해 재편입 또는 감점합니다. 동일 조합을 제거하고 최종 5조합 사이 공통 번호는 3개 이하로 제한합니다. 후보 수는 2천~100만 중 선택하며 실제 실행 수·시드·공통 점수식을 표시합니다. 기본 설정은 2천으로, 실행하지 않은 100만 후보를 계산했다고 표시하지 않습니다.

실행일 기준 최근 15년을 달력상 10년/3년/2년으로 나눕니다. 학습 10년 중 앞부분은 통계 초기화, 마지막 52회는 기여도 탐색에 사용합니다. 검증 3년의 모든 회차에서 17개 후보를 비교하고 마지막 2년은 사전 동결 후보와 기본·무작위만 평가합니다. 각 대상 회차 이전 전체 이력만 사용하며 최종 평가로 후보를 다시 탐색하지 않습니다. 검증과 최종 생성은 같은 후보 수·규칙을 사용합니다. 8회차 블록 부호반전 검정/부트스트랩 4096회 및 다중비교 보정을 사용하며, 유의하고 안정적인 개선이 없으면 기본 가중치를 유지합니다. 미실행 상태는 수치를 생성하지 않습니다.

배포 시 scripts/publish-advanced.ts가 실제 313회차(2026-10-21 기준)를 자동 검증하고 데이터 지문이 일치하는 추천 결과를 준비합니다. 사용자는 직접 검증할 필요가 없습니다. 수동 재현: npx tsx scripts/verify-advanced.ts 2000. 요약은 reports/advanced-summary.json, 큰 원본 실행 기록은 로컬 reports/advanced-validation.json에 저장됩니다. 화면에서 사용자 실행의 결과 JSON도 내려받을 수 있습니다. 배포 사전 검증의 회차별 원본 기록은 GitHub Actions collection-status 자료에 보관합니다. 데이터 부족·미검증 출처·미완료 계산은 검증된 최적화로 적용하지 않습니다.



## 최근 이름 관리와 QR 이력

이름 목록 관리 링크: https://stp-repository.github.io/lotto-best-choice/#/admin/names . 게임 화면과 메인 하단에도 링크가 있습니다. 이 관리 도구는 현재 브라우저의 최근 이름 목록만 추가·수정·삭제합니다. 공용 사용자 명부나 로그인 권한을 가진 서버 관리자 기능은 아닙니다. 최근 이름 목록은 최대 50개이며, 게임에 실제로 같은 이름을 여러 번 입력하는 것을 막지 않습니다.

QR 확인 이력은 최근 100건을 브라우저에 보관합니다. 당첨 이력은 이름을 비우지 않습니다. 이름을 직접 입력하면 그 이름으로 기록하고 미입력·취소 시 자동 생성한 랜덤 별명을 유지합니다. 랜덤 별명 버튼으로 다시 만들 수도 있습니다. 추첨 대기 복권은 결과 데이터가 들어오면 재비교하고, 당첨되면 별명을 자동 부여합니다. 확인 이력은 다시 보기와 개별 삭제가 가능합니다.

대시보드는 기존 목록을 유지하고, 별도 15년 통계 분석·과거 예측 검증 메뉴는 숨겼습니다. 통합 번호 생성은 결과 5조합을 먼저 표시하며 분석 상세와 검증 수치는 접힌 영역에서 확인합니다.
