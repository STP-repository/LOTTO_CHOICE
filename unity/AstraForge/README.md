# 아스트라 포지 — Unity 기반 토너먼트 조합 디펜스

현재는 **PHASE 1 기반 + 로컬 전투 프로토타입**입니다. 실제 인터넷 멀티플레이, Android/iOS 빌드, 출시용 그래픽이 완료된 게임이 아닙니다.

## 환경

- 목표 Editor: Unity 6000.3.26f1 (6.3 LTS). 공식 릴리스: https://unity.com/releases/editor/whats-new/6000.3.26f1
- 작업 PC에는 Unity Editor/Hub가 없어 Unity 컴파일·씬 실행·모바일 빌드를 검증하지 못했습니다.
- .NET SDK 10.0.401에서 Unity 의존성이 없는 동일 C# Core를 netstandard2.1로 컴파일하고 검증했습니다.
- NGO/Multiplayer Services/Photon을 검토했지만 Editor/실제 패키지 설치 호환성을 확인하지 못해 아직 네트워크 SDK를 고정하지 않았습니다. `Packages/manifest.json`은 기본 Unity 모듈만 사용합니다.

## 열기

1. Unity Hub에서 이 폴더를 프로젝트로 추가합니다.
2. 위 Editor와 Android Build Support를 설치합니다. iOS 최종 앱 서명·빌드는 macOS/Xcode 환경에서 별도 검사해야 합니다.
3. 메뉴 `Astra Forge → Create prototype assets and scene`을 실행합니다. 독립 영웅 카탈로그 ScriptableObject와 Prototype 씬을 생성합니다. 기존 카탈로그는 덮어쓰지 않습니다.
4. `Assets/Scenes/Prototype.unity`에서 Play. 시작 UI의 2~8명은 **로컬 봇 수**이며 실제 인터넷 참가자로 표시하지 않습니다.
5. 소환, 빈 칸 이동, 동일 영웅3개 합성, 지정 레시피, 강화, 자동 공격과 대진 진행을 시험할 수 있습니다. 배치 후 선택은 해제됩니다.

## 고정 규칙

|인원|팀 크기|실제 경기 수|
|--|--|--:|
|2|1·1|1|
|3|1·1·1|2|
|4|2·2|1|
|5|1·1·1·1·1|4|
|6|2·2·2|2|
|7|1·1·1·1·1·1·1|6|
|8|2·2·2·2|3|

모든 경기는 1:1 또는 2:2입니다. 3:3·4:4·전체 협동 모드는 없습니다. 부전승 배치와 팀·대진은 시드로 결정합니다. 중복 결과는 다시 반영하지 않고 다른 결과로 덮어쓰려 하면 거부합니다. 동점은 재경기 상태입니다.

## 구현 경계

- `Core/Domain.cs`: 다섯 영웅 등급, 독립 영웅10종, 레시피, 데이터 검증, 시드 난수.
- `Core/Tournament.cs`: 2~8명 팀 구성, 부전승, 대진 전파, 방 준비/시작 중복 거부.
- `Core/Battlefield.cs`: 팀 공유40칸, 개별 소유권·자원, 원자적 합성/지정 조합, 기본 단일 공격, 체력·보상, 경로 순환, 누적 제한/보스 시간 초과 패배, 10웨이브 프로토타입.
- `Core/BalanceSettings.cs`: 검증한 설정 스냅샷. 경기 중 원격 변경으로 기존 경기 설정을 바꾸지 않습니다.
- `Presentation/RemoteSettings.cs`: 공개 읽기 전용 설정을 받아 **다음 경기**에 사용. 실패하면 오프라인 기본값이라는 안내를 표시합니다. Editor가 없어 실제 Unity HTTP 실행은 미검증입니다.
- `Presentation/DemoBootstrap.cs`: 원작 이미지 없이 기본 도형으로 만든 로컬 전장/캐릭터, 풀링48개 공격선, 체력바, 기본 UI. 최종 캐릭터/스킬 그래픽이 아닙니다.

범위·연쇄·관통·지속피해 등은 데이터에 구분되지만, 현재 피해 적용은 기본 단일 공격입니다. 영웅 고유 스킬·기절·둔화·출시용 이펙트는 PHASE 4/9입니다. 데이터를 마련한 것을 기능 완료라고 보고하지 않습니다.

## 관리자

소유자 전용 기존 관리자 사이트의 `/astra`에서 계정/영웅 레벨, 차단, 영구 아이템 지급·회수, 소환 확률, 비용, 몬스터 제한/체력 성장/웨이브·보스 시간, 변경 이력을 관리합니다.

계정·아이템은 서버 저장까지 구현했고 **Unity 온라인 계정 인증/조회/소비 연동은 PHASE 5 이후**입니다. 로컬 봇을 실제 계정으로 가장하지 않습니다. 레벨/차단 변경이 로컬 프로토타입에 적용됐다고 주장하지 않습니다.

## 검증

```powershell
dotnet run --project Verification/Verification.csproj
```

검증은 실행 가능한 콘솔 assertion 러너이며 Unity Test Runner 실행 결과가 아닙니다. 2~8명 각각100시드 대진, 소유권/중복 차감/합성/경제/전투/웨이브/동점을 검사합니다. 웹 관리자 API는 별도 임시SQLite에서 인증·리비전 충돌·중복 지급·음수 재고·설정 합계·감사 로그를 검사합니다.
